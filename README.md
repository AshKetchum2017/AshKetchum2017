🧠 How I Build Things

I like starting from practical problems.

If something is repetitive, inefficient, or unnecessarily complicated, I'll probably wonder whether I can automate it.

My projects are also my learning environment. I build something, break something, understand why it broke, refactor it, and repeat.

I don't know everything.

But I'm very good at asking:

«"What happens if I try this?"»
